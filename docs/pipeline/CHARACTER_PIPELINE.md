# 캐릭터 픽셀 파이프라인 (Game Character Production Pipeline)

> 이 폴더의 `PIXEL_SPRITE_PIPELINE.md` · `pxl.py` · `restore_master.py`는 기획자가 넣은 원본(claude.ai 에서 먼저 해 본 "AI 도트풍 원화 → 격자 복원" 기록)이고 고치지 않는다. 이 문서는 그 길을 NX-07 로 고쳐 밟은 과정(기획서 9.11 ~ 9.11.6)을 다른 캐릭터에도 같은 순서로 밟게 묶은 설명서다.

처음 보는 에이전트와 기획자가 함께 읽는다. 도구는 `tools/pixpipe.py` 하나이고, 캐릭터마다 설정 파일 하나(`art/characters/<id>/pixel/pipeline.json`)만 채우면 된다. 채운 예는 NX-07 의 설정 파일이다. 기획자가 혼자 화면으로 밟으려면 **`픽셀스튜디오.bat`** (12장).

## 1. 한눈에

```
 설정화 묶음 (정면 · 측면 · 후면 …)          ← 이미 있다 (기획서 9.4.1, charpipe 등록)
      │
 ① 등록 · 원화 검사 ─────────────── charpipe register / build
 ② 도트판 단순화안 ◆ ────────────── 기획자 (에이전트가 [제안])
 ③ 1단계 뽑기: 밑그림 없이 자유 설계 ─ pixpipe s1      (fal.ai, 밝기 계획마다 1장)
 ④ 밑그림: 목표 칸 수로 다시 깔기 ──── pixpipe guide   (머리 비율 보정)
 ⑤ 2단계 뽑기: 격자 그대로 다시 그리기  pixpipe s2      (fal.ai, 후보마다 1장)
 ⑥ 마스터: 칸 읽기 · 색 묶기 · 칸 손보기 pixpipe master
 ⑦ 재기 → ⑧ 비교 그림 ──────────── pixpipe measure · compare
 ⑨ 기획자가 고름 ◆ ─────────────── pixpipe pick
 ⑩ 층 더하기 (스카프 같은 것, 있으면) ─ pixpipe layer   (변형이 여럿이면 ◆ 고름)
 ⑪ 승인 기록 ◆ ─────────────────── pixpipe approve
 ⑫ 규격 (승인된 그림에서 잰다) ────── pixpipe spec
 ⑬ 애니메이션: 대기 = 변형, 달리기 = 표 pixpipe rig-init · anim   (검사 · 시트 · GIF · 비교 그림)
    + 승인된 다른 캐릭터와 함께 ─────── pixpipe together  (두 번째 캐릭터부터)
 ⑭ 기획자 평가 ◆ ───────────────── pixpipe review
      │
 보고 화면 art/characters/index.html ── pixpipe report (= charpipe build)
```

◆ = 사람이 정하는 곳. 도구는 대신 정하지 않는다. 어디까지 왔는지는 `python -X utf8 tools/pixpipe.py status <id>` 또는 보고 화면의 '픽셀 파이프라인' 칸에서 본다 (됨 / 기획자 결정 대기 / 아직).

## 2. 단계마다 누가 무엇을 하고 무엇이 나오는가

명령은 모두 `python -X utf8 tools/pixpipe.py …`다. 결과는 `art/characters/<id>/pixel/work/`(작업 파일), `art/prompts/pipeline/<id>/`(프롬프트 · 밑그림), `art/characters/<id>/pixel/`(승인된 마스터 · 규격), `art/characters/<id>/anim/`(애니메이션)에 생긴다.

| # | 단계 | 누가 | 명령 | 나오는 것 |
|---|---|---|---|---|
| ① | 등록 · 원화 검사 | 에이전트 | `charpipe.py register` (설정화 묶음) · `charpipe.py build` | `character.json` · `check.json`. 원화 검사가 실패면 멈춘다 |
| ② | 도트판 단순화안 | 기획자 (에이전트가 `[제안]`) | `pipeline.json`의 `simplify`를 채운다 | 지킬 것 / 합칠 것 / 뺄 것과, 프롬프트에 들어갈 영어 한 문장 |
| ③ | 1단계 뽑기 | 에이전트 + fal.ai | `s1 <id> [--plan A] [--dry-run]` | `work/s1/<id>_s1_<안>.png`. 칸이 고르지 않은 도트풍 그림 (그게 정상이다). 자세 · 덩어리 · 밝기를 모델이 설계한다 |
| ④ | 밑그림 | 에이전트 | `guide <id>` | `prompts/guide_<후보>.png` (1024, 마젠타, 목표 칸 수의 격자). 머리와 몸을 따로 줄여 `heads_guide` 등신으로 맞춘다 |
| ⑤ | 2단계 뽑기 | 에이전트 + fal.ai | `s2 <id> [--job C36] [--dry-run]` | `work/s2/<id>_s2_<후보>.png`. 밑그림의 격자 그대로 깨끗하게 다시 그린 그림 |
| ⑥ | 마스터 | 에이전트 | `master <id>` (손볼 칸은 설정의 `jobs.<후보>.fixes`) | `work/<후보>/<id>_<후보>_master.png` (1배) · ×8 · 팔레트 · info · 손보기 전(`_unfixed`)과 `_fixes.json`. 격자에 맞은 칸이 90% 아래면 경고한다 |
| ⑦ | 재기 | 에이전트 | `measure <id>` | `work/measure.json`. 형식(통과 / 실패)과 그림(참고 그림과의 거리)을 따로 (8장) |
| ⑧ | 비교 그림 | 에이전트 | `compare <id>` | `work/compare.png`: 후보마다 1단계 · 밑그림 · 2단계 · 마스터 · 어두운 게임 화면과 숫자. 참고 그림이 PC 에 있으면 그것과 나란히 놓은 그림을 공개하지 않는 `reference/pixel_style/analysis/`에 따로 |
| ⑨ | 고름 | **기획자** | `pick <id> --job <후보> --quote "원문"` | 설정의 `decisions.pick` + 등록부의 `records` |
| ⑩ | 층 더하기 | 에이전트 | `layer <id>` (표는 설정의 `layers`) | `work/layers/<id>_<층>_<변형>.png`. 층 밖의 칸이 하나라도 바뀌면 멈춘다. 변형이 여럿이면 기획자가 `pick --layer 층=변형` |
| ⑪ | 승인 | **기획자** | `approve <id> --quote "원문" --saw <본 그림>` | 고른 마스터(와 층 변형)를 `<id>_px_base.png` · `<id>_px_<층>.png`로 복사하고 등록부에 올려 승인을 적는다 (그때의 해시와 함께) |
| ⑫ | 규격 | 에이전트 | `spec <id>` | `<id>_px_spec.json` · `.png`: 캔버스 · 키 · 부위 줄 · 부위마다 칸 수 · 팔레트(색마다 칸 수와 놓인 줄) · 층이 덮고 더하는 칸 · 바뀌면 안 되는 부분 `[제안]` |
| ⑬ | 애니메이션 | 에이전트 | `rig-init <id>` → (달리기는 다리 자세 표를 찍고) → `anim <id>` | `anim/rig.json`(표) · `anim/<동작>/timeline.json` → 프레임 PNG · `check.json` · 시트 · 메타 JSON · ×8 GIF · `anim/preview/compare.png` · 게임 화면 GIF. `rig-init`이 쓴 대기(변형)는 표를 하나도 찍지 않고 바로 돈다 |
| ⑬+ | 함께 세우기 | 에이전트 | `together <id> --with nx07:scarf [idle run]` | `anim/preview/together_<다른 id>_<동작>_320x180_x4.gif`: 승인된 다른 캐릭터와 같은 어두운 게임 화면 · 같은 발바닥 줄. 동작마다 자기 틱으로 돌고, 두 박자가 다시 맞는 데까지 (GIF 시간은 10ms 단위로 누적해 맞춘다) |
| ⑭ | 평가 | **기획자** | `review <id> --quote "원문"` | 설정의 `decisions.review` + 등록부의 `records` (평가는 승인이 아니다) |
| | 보고 화면 | 에이전트 | `report` | `art/characters/index.html` (더블클릭으로 연다) |

## 3. 기획자가 정하는 곳과 거기서 보게 될 그림

| 곳 | 기획자가 보는 것 | 정하는 것 | 결정이 없을 때 |
|---|---|---|---|
| ② 단순화안 | 설정화 · 에이전트가 쓴 `[제안]` (지킬 것 / 합칠 것 / 뺄 것) | 이 작은 크기에서 무엇을 남기고 무엇을 뺄지 | **`[제안]`으로 진행한다.** 뽑기 기록(`gen_log.json`)에 "[제안]으로 진행"이 남는다. 고르기(⑨)를 할 때 결과 그림으로 함께 판단한다 (NX-07 이 그랬다) |
| (뽑기 상한) | — | 이 캐릭터에 쓸 이미지 생성 횟수 (`generate.budget`) | 비어 있으면 뽑기가 멈춘다. 넘으면 멈춘다 (`--over-budget`은 기획자에게 물은 뒤) |
| ⑨ 고름 | `work/compare.png` | 후보 가운데 하나 (밝기 계획 × 키) | **멈춘다.** 층 · 승인은 무엇에 대한 것인지 정해지지 않으므로 돌지 않는다 |
| ⑩ 층의 변형 | 층 변형의 비교 (`compare.png`의 층 줄) | 색 · 모양 | 승인이 멈춘다 |
| ⑪ 승인 | 고른 마스터 (와 층 변형) | 이 그림을 이 캐릭터의 픽셀 마스터로 삼는다 | **규격 · 애니메이션이 멈춘다.** 승인 전에 대기를 보여 주려면 `--allow-unapproved`로 돌리고, 결과(`check.json` · 규격)에 "승인 기록 없음"이 찍힌다 |
| ⑭ 평가 | `anim/preview/compare.png` · 게임 화면 GIF | 받아들인다 / 고칠 것 | 다음 동작(걷기 · 점프)으로 가지 않는다 |

- 기획자의 말은 원문 그대로 `--quote`에 넣는다. 에이전트가 읽어 낸 뜻은 `[해석]`으로 적는다.
- 고른 뒤 그림을 손보면(칸 하나라도) 승인 해시가 달라져 등록부 검사가 실패로 보인다. 다시 승인을 받는다.

## 4. 설정 파일 `pipeline.json`

`pixpipe init <id>`가 빈 틀을 만든다 (값은 비어 있다. 지어내 채우지 않는다). 영어 칸은 프롬프트에 그대로 들어간다.

| 칸 | 무엇 | 누가 정하나 | NX-07 의 값 |
|---|---|---|---|
| `size.height_cells` | 목표 키 (칸) | 기획자 | 36 |
| `size.heads_guide` | 밑그림의 머리 비율 목표 (정수리 ~ 목) | 에이전트 `[제안]` | 3.2 (결과는 3.4 ~ 3.6등신으로 잰다) |
| `screen.size` | 화면 밀도 (비교 그림 · 게임 화면 GIF) | 기획자 (지금은 `[제안]`) | 320×180 |
| `generate` | 모델 · 크기 · 인자 · **상한(budget)** | 상한은 기획자 | gpt-image-2.6 · 1024² · 7회 |
| `references` | 1단계 참조 그림과 그 역할(영어). 밑그림은 넣지 못한다 | 에이전트 | 설정화 측면 · 정면 |
| `prompt` | 공통 틀(`art/prompts/pipeline/_stage1.txt` · `_stage2.txt`)의 `{칸}`을 채우는 캐릭터 문장: 몸 · 자세 · 강조 획 · 채도 높은 곳 · 2단계의 머리와 팔 문장 등 | 에이전트 | 그때 통한 문장 그대로 |
| `simplify` | 도트판 단순화안: `keep` · `merge` · `drop`(한국어) + `prompt`(영어 한 문장) + `status`(`결정` / 비면 `[제안]`) | 기획자 (에이전트 `[제안]`) | 귀 장치를 헬멧 톤으로 · 흰 판과 시안 점 빼기 · 올리브를 어둡게 |
| `plans` | 밝기 계획의 변형. 안마다 1단계 문장들(`s1`)과 2단계 한 문장(`s2`). 목을 자동으로 못 찾으면 `head_px`(1단계 그림의 정수리 ~ 턱, 원본 px, 손으로 잰다) | 에이전트 `[제안]` | A 어두운 몸 / B 올리브 장갑 / C 어두운 몸 + 뒤 빛 (`head_px` 없음) |
| `jobs` | 2단계 후보: 어느 안 · 키 몇 칸 · 밑그림 칸 px · 손볼 칸(`fixes`) | 에이전트 | A36 · C36 · C48 · B48 |
| `palette` | 색 묶기: 최대 색 수 · 멈추는 거리(Lab ΔE) | 고정 | 16 · 14 |
| `layers` | 층(몸 위에 얹는 것): 색 · 칸 표(글자 하나 = 칸 하나) · 덮으면 안 되는 칸(`protect`) · 변형들 | 에이전트 `[제안]`, 변형은 기획자가 고름 | 스카프 S1 ~ S4 |
| `spec.parts` | 바뀌면 안 되는 부분을 나눌 줄: 머리 · 몸통 · 다리 · 앞쪽 팔 사각형 | 에이전트 (승인된 마스터를 보고) | 머리 0~10 · 몸통 11~24 · 다리 25~35 · 팔 (0,16)-(4,24) |
| `spec.parts.free` · `near_arm_label` | 머리 · 몸통 띠 안에서 **바뀌어도 되는 칸**의 사각형 (긴 머리카락의 끝 · 소매 끝의 손). 그 밖의 머리 · 몸통 칸은 프레임마다 마스터와 같아야 한다 (검사 `fixed_same_all`). 없으면 NX-07 처럼 머리만 통과 조건 | 에이전트 `[제안]` | 없음 (미리네: 머리카락 끝 · 앞쪽 손) |
| `spec.hand_measured` · `part_labels` | 자동 측정이 틀리는 캐릭터의 손으로 잰 값 (규격에 함께 적힌다) · 규격 그림의 부위 이름 | 에이전트 | 없음 (미리네: 머리 10칸 · 3.0등신) |
| `spec.palette_names` · `materials` · `rules` · `simplified` | 색의 쓰임 이름 · 재질마다 톤 · 지킬 규칙(방향 · 외곽선 · 빛) | 에이전트 | |
| `anim` | 캔버스 · 기준점 · 마스터에서 기준점의 x · 만들 동작 | 에이전트 `[제안]` | 40×40 · (20, 38) · x 8 · idle, run |
| `decisions` | 기획자의 결정 (`pick` · `approve` · `review`가 적는다) | 손으로 쓰지 않는다 | |
| `pinned` (plan · job 안) | 파이프라인 전에 만든 파일을 가리킨다 (NX-07 만) | | 실험 폴더의 원본 |

## 5. 이미지 생성 횟수의 어림

| | 횟수 | 내용 |
|---|---|---|
| NX-07, 이 방법 (v2) | **7** | 1단계 3 (밝기 계획 A · B · C) + 2단계 4 (A36 · C36 · C48 · B48) |
| NX-07, 방법을 찾기까지 | 10 더 (합 17) | 9.11 E2 4 · 9.11.1 견본 3 · 9.11.2 v1 3 — 새 캐릭터는 되풀이하지 않는다 |
| 새 캐릭터 어림 | **5 ~ 7**, 다시 뽑기를 넣어 8 ~ 10 | 1단계 2 ~ 3 + 2단계 3 ~ 4. 격자가 90% 아래로 나온 후보 · 오타처럼 엉뚱한 그림은 다시 뽑는다 |

설정화 묶음(일곱 장)은 이미 있다고 본다. 층 · 규격 · 애니메이션은 이미지 생성 0회다.

## 6. 지킬 원칙과 그 근거가 된 실패

| 원칙 | 근거 |
|---|---|
| 1단계에는 밑그림을 넣지 않는다. 자세 · 덩어리 · 밝기는 모델이 설계하게 한다 (도구가 막는다) | v1(9.11.3): 뻣뻣한 선 자세의 밑그림을 줬더니 모델이 그대로 옮겼다 |
| 어두운 색을 막지 않는다 ("Dark colors are welcome") | v1: "검정은 쓰지 말라 · 슈트는 밝게"라고 적어 주인이 되는 어두운 덩어리를 스스로 막았다 |
| 부품을 같은 무게로 나열하지 않는다. 밝기 계획(주인 덩어리 + 작은 강조 획)을 쓴다 | v1: 부품이 같은 크기 조각으로 쌓여 주인이 되는 덩어리가 없었다 (가장 큰 밝기 덩어리 15%) |
| 크기와 격자는 글이 아니라 그림(밑그림)으로 준다 | 9.11: 모델은 칸 수를 세지 못한다 (64칸 주문 → 90칸) |
| 억지로 줄이지 않는다. 그 크기에서 다시 그리게 한다 | 9.11 · 9.11.1: 정수가 아닌 비율로 줄이면 눈 · 엠블럼이 무너졌다 |
| 형식만 재고 성공이라 하지 않는다. 그림을 따로 재고, 마지막은 기획자의 눈 | 9.11.3: 격자 100% · 16색 · 반투명 0 인 v1 이 "너무 별로"였다 |
| 체형을 글로 '가늘다 · 길다'고 적지 않는다. 설정화를 참조로 넣는다 | CLAUDE.md · 9.6: 여성스럽게 나왔다 |

## 9. 새 캐릭터를 시작하는 순서 (체크리스트)

1. `docs/STORY.md` 4장(그 캐릭터) · 이 문서 · `art/characters/nx07/pixel/pipeline.json`(채운 예)을 읽는다.
2. `python -X utf8 tools/charpipe.py build` — 등록과 원화 검사가 통과인지 본다. 등록이 없으면 `charpipe.py register`.
3. `python -X utf8 tools/pixpipe.py init <id>` (이미 있으면 건너뛴다). `_available_files`에 등록된 설정화가 나열되어 있다.
4. 기획자와 정한다 (또는 `[제안]`으로 적고 알린다): 목표 키 칸 수 · 생성 상한 · 단순화안 · 층이 있는가.
5. `pipeline.json`을 채운다: `references` · `prompt` · `simplify` · `plans`(2 ~ 3안) · `jobs` · `size` · `screen`. 영어 문장은 NX-07 의 것을 본보기로 그 캐릭터에 맞게 새로 쓴다 (부품 목록이 아니라 밝기 계획을).
6. `pixpipe prompts <id>` → `art/prompts/pipeline/<id>/s1_*.txt`를 읽어 확인한다. `pixpipe s1 <id> --dry-run`으로 보낼 참조를 확인한다.
7. `pixpipe s1 <id>` → 1단계 그림을 눈으로 본다 (자세 · 덩어리 · 체형 · 다른 게임 캐릭터를 닮지 않았는가).
8. `pixpipe guide <id>` → 밑그림의 1배 그림(`work/guides/*_cells_x8.png`)을 본다. 머리가 눌렸으면 `heads_guide`를 바꿔 다시. 얼굴이 위아래로 끊겼으면(머리 · 몸의 배율 경계가 얼굴을 지난다) 목을 잘못 찾은 것이다: `guides.json`의 `src_head_px`를 1단계 그림의 턱과 견주고, 다르면 그 안의 `head_px`에 턱까지의 px 를 적고 다시 (11장).
9. `pixpipe s2 <id>` → `pixpipe master <id>` → 격자 90% 아래 후보는 다시 뽑을지 판단. 손볼 칸은 `fixes`에 이유와 함께 적고 `master`를 다시 돈다 (새 색을 만들지 않는다).
10. `pixpipe measure <id>` → `pixpipe compare <id>` → **기획자에게 `work/compare.png`를 보이고 묻는다.**
11. 기획자의 말 → `pixpipe pick <id> --job … --quote "원문"`. 층이 있으면 `pixpipe layer <id>`, 변형이 여럿이면 다시 보이고 `pick --layer`.
12. **기획자의 승인** → `pixpipe approve <id> --quote "원문" --saw work/compare.png`.
13. `pipeline.json`의 `spec.parts`(긴 머리 · 옷자락이 있으면 `free`도) · `palette_names` · `anim`을 채우고 `pixpipe spec <id>` → **규격 그림의 숫자를 눈으로 확인한다** (머리 · 등신은 `hand_measured`로) → `pixpipe rig-init <id>` → `pixpipe anim <id>` (대기).
14. 달리기: `anim/rig.json`에 다리 자세 표(`leg_poses`) · 앞쪽 팔 자세(`arm_poses`) · 층의 끝(`tails`)을 찍고, `anim/run/timeline.json`을 쓴다 (NX-07 의 `art/characters/nx07/anim/`이 본보기). `anim`에 `run`을 더하고 `pixpipe anim <id>`. 검사가 통과해야 쓴다.
15. 두 번째 캐릭터부터: `pixpipe together <id> --with nx07:scarf`. 프레임 줄과 GIF 를 프레임 단위로 풀어 눈으로 본다.
16. **기획자에게 `anim/preview/`를 보이고** 말을 `pixpipe review`로 적는다. `pixpipe report`.
17. 기획서(GAME_DESIGN.md 9.11 아래)에 소절을 쓴다: 정한 것 · 숫자 · 안 된 것(정직하게) · `[미정]`.

## 12. 스튜디오로 하기 (기획자가 혼자, 2026-11-19, 기획서 9.11.10)

|---|---|---|
| 목록 | 등록부의 캐릭터와 단계 (14칸 막대) | `status` |
| 새 캐릭터 | 이름 · 식별자(이름에서 제안) · 종류 · 키(cm) · 원화(측면 / 정면 / 후면 / 그 밖). 그림인지 확인하고 PNG 로 바꿔 `art/characters/<id>/upload/`에 둔다 | `charpipe register` · `add` (`up_<종류>_<n>`, 그룹 design) · `pixpipe init` |
| 만들 준비 | 목표 키(칸) · 화면 · 밝기 계획 변형 수 · 생성 한도 · 머리 비율 · 메모(꼭 지킬 것 / 빼도 되는 것 / 주인 덩어리) | `pixpipe defaults <id> --form …` |
| 픽셀 만들기 | 생성 횟수와 남은 한도를 보이고 확인 → 1단계 → 밑그림 → 2단계 → 마스터 → 재기 → 비교 그림 → 함께 세우기 → 등록부 → 보고 화면 | `s1` · `guide` · `s2` · `master` · `measure` · `compare` · `lineup` · `candidates` · `report` |
| 리뷰 | 후보를 같은 배율로 · 형식과 그림 숫자 따로 · 1단계 · 밑그림 · 2단계 펼치기 · 승인된 캐릭터와 같은 칸 크기 · 어두운 게임 화면 · 칸 손보기 · 고름 / 승인 / 채택하지 않음 · 다시 뽑기 | `fix` · `unfix` · `pick` · `approve` · `reject` · `defaults --add` |
| 동작 | 이미 만든 GIF 를 보고 평가를 적는다. **동작 만들기는 에이전트의 일** | `review` |
| 기록 | 등록부의 records · 승인 · 생성 기록 | (읽기만) |

**명령줄과의 관계**: 스튜디오는 위 명령을 셸 없이 인자 목록으로 부른다. 기록(`pipeline.json`의 `decisions` · `fixes`, `gen_log.json`, 등록부의 `records` · `approvals`)은 명령줄로 한 것과 같은 모양이다. 스튜디오로 시작한 캐릭터를 에이전트가 명령줄로 이어 가도 된다 (규격 · 동작은 지금 그렇게 한다). 결정의 `saw`에는 "스튜디오 리뷰 화면"과 그때 본 그림(후보 · `work/lineup_screen.png` · `work/compare.png`)이 적힌다.

**캐릭터에 묶이지 않은 기본 문장**: `art/characters/_pipeline/studio_defaults.json` `[제안]`. NX-07 · 미리네에서 통한 문장을 일반화했다. 체형은 글로 적지 않고 그림에서 읽게 한다 · 밝기 계획 세 가지(① 어두운 몸 + 뒤 빛 — 승인된 두 마스터가 모두 이것 ② 밝은 덩어리가 주인 ③ 중간 톤) · 얼굴 둘레의 작은 장치는 1칸 또는 뺀다 · 승인된 NX-07 마스터를 1단계 칸 크기로 키운 그림을 '그리는 방식의 기준'으로 넣는다. 기획자의 메모는 원문(한국어)으로 들어간다 (`{ }`는 괄호로 바뀐다). 손으로 쓴 설정(`studio` 표시가 없는 NX-07 · 미리네)은 `defaults`가 덮지 않는다.

**비용 확인**: '픽셀 만들기'는 누르기 전에 이번 생성 횟수(없는 1 · 2단계 그림만), 한도, 지금까지, 끝난 뒤를 보이고 확인을 받는다. 확인한 횟수와 서버가 다시 센 횟수가 다르면 멈춘다. 한도를 넘으면 버튼이 막힌다 (한도는 만들 준비 · 다시 뽑기에서 기획자가 올린다). `pixpipe gen`의 한도 검사도 그대로다.

**지키는 것**: 승인된 캐릭터(NX-07 · 미리네 · 앞으로 승인할 캐릭터)는 다시 뽑기 · 칸 손보기 · 고름이 막힌다 (보기와 동작 평가만). 칸 손보기는 그 그림에 이미 있는 색(또는 투명)만 쓴다 (`from` = 같은 색의 다른 칸). 서버는 `127.0.0.1`에만 묶이고, 켤 때 만든 토큰 · `Host` · `Origin` · `Sec-Fetch-Site`를 본다. 내주는 파일은 `art/characters/` · `art/concept/setting/` · `art/prompts/pipeline/` · NX-07 의 옛 후보 폴더의 그림 · 표 · 글뿐 (`.env.local` · `reference/` · 코드는 내주지 않는다). `pixpipe gen`은 `reference/pixel_style/`의 그림을 생성기에 보내지 않는다.

**연습 (시험 방식)**: `python -X utf8 tools/pixstudio.py --practice` — 화면 위에 보라색 '연습 모드' 띠. 뽑기가 fal.ai 대신 미리네의 1 · 2단계 그림을 복사한다 (`PIXPIPE_MOCK_FROM=mirine`, 기록에 `mock`). 화면과 기록의 흐름을 비용 없이 시험하는 것이고, 연습으로 만든 캐릭터는 시험이 끝나면 지운다 (`art/characters/<id>/` · `art/prompts/pipeline/<id>/` · 등록부의 줄 → `charpipe build`). 연습의 후보는 격자가 맞지 않을 수 있다 (다른 캐릭터의 2단계 그림을 이 캐릭터의 밑그림 격자로 읽기 때문).

**문제가 났을 때**

| 보이는 것 | 할 일 |
|---|---|
| '실패한 곳: …' 빨간 상자 | 까닭을 읽는다. 이미 뽑은 그림은 남아 있다. '실패한 곳부터 다시 만들기'는 없는 그림만 뽑는다 |

| 다른 작업이 돌고 있다 | 한 번에 한 작업. 위 띠의 작업이 끝나기를 기다린다 |
